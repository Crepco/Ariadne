## Abstract

Active Directory (AD) attack paths — chains of individually-benign misconfigurations
that escalate a low-privilege account to Domain Admin — are today surfaced by
BloodHound's *rule-based* Cypher queries. We ask whether a modern LLM agent can perform
the human analyst's role instead: exploring the AD graph step by step, through a small set
of query tools, and proposing a valid attack path on its own. We evaluate on synthetic
graphs that conform to the BloodHound schema, which lets us control graph size and compute
exact ground truth. We report path-correctness, hallucination rate, tool-call efficiency,
time-to-solution, and how these scale with graph size, all against the BloodHound-equivalent
shortest-path baseline.

## 1. Introduction

BloodHound maps an AD forest into a graph of principals (users, groups, computers) and
control edges (`MemberOf`, `AdminTo`, `GenericAll`, `ForceChangePassword`, …), then runs
pre-written queries such as "shortest path to Domain Admins." Because it is rule-based, it
finds exactly the patterns its queries encode; unusual-shaped chains still require a human
to reason over the graph. This work measures whether an LLM agent can do that reasoning, and
how it compares to the rule-based baseline on identical data.

## 2. Method

- **Data.** A seeded generator (`seed=1337`) writes a structurally realistic AD graph
  directly into Neo4j — no Windows lab. Two known misconfiguration chains are *planted*
  (`ForceChangePassword→MemberOf→GenericAll` and `GenericWrite→AddMember→MemberOf`) so a
  subset of runs has a known-correct answer; the remaining start users are random.
- **Agent.** A minimal ReAct loop (reason → act → observe) with four tools:
  `search_node`, `query_outbound_edges`, `query_inbound_edges`, `check_path_exists`. The
  agent is never shown the whole graph — it must explore, like a human in BloodHound.
- **Baseline (ground truth).** The Cypher `shortestPath` over the same traversable edge set
  is the BloodHound-equivalent answer key.
- **Scoring.** The agent's proposed path is verified *hop by hop*: every claimed edge must
  exist in the graph, and the chain must reach Domain Admins. A claimed hop with no
  matching edge (or an unresolvable node) counts as a hallucination.

## 3. Experimental setup

- **Model:** `gemini-3.1-flash-lite` (single model; a second model is future work).
- **Graph sizes:** swept across several node counts to produce a scaling curve.
- **Starts per graph:** the planted-chain users plus N random users (some unreachable, to
  test whether the agent hallucinates a path where none exists).
- **Reproduce:** `python experiments/run_benchmark.py` → writes
  `experiments/logs/results.csv`, `results/*.png`, and `results/metrics.md`.

**Reading it.** On the 8 solvable cases (all planted chains, both sizes) the agent
found a valid path every time, at the ground-truth optimal length, with no
hallucinated edges (~3.5 tool calls each). The two misses were randomly-sampled
users with **no path to Domain Admins**: the agent failed to conclude `NO PATH` and
exhausted its 12-step budget (logged as *incomplete*, not a hallucination). So the
headline finding of this pilot is: **accurate and non-hallucinatory on solvable
instances, but poor at recognising unsolvable ones.** (Sample size is tiny — this is
a plumbing-validation run, not the final sweep.)

## 5. Limitations

- Synthetic-only data; a single model; graphs from one generator's random structure.
- Because the baseline traverses the same edge set, "paths BloodHound misses" cannot arise
  here — the interesting gap is agent *misses* and *hallucinations*, which we report.

## 6. Ethics

All experiments use synthetic, locally-generated data conforming to the BloodHound schema.
No live network is involved. Any future live-collection step would only ever run against an
environment we own or are explicitly authorised to test.

## 7. Future work

Validation on live-collected AD data; a second/stronger model for comparison; larger graphs
and additional attack primitives (e.g. Kerberoasting, ACL-based DCSync chains).
